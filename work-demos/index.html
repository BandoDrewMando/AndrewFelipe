Online subscription emails

#6002 #6024 #6054 #6055

Publishers started requiring a separate email address for every copy of an online subscription, so a library with three copies had to come up with three addresses. I built a place on each customer to keep those addresses, plus aliases that forward to the library's real inbox through Mailgun, so WT Cox can supply as many as an order needs.         How aliases are made (#6002)
        
An alias is u plus four random hex digits on WT Cox's mail domain. Its Mailgun route matches the alias, forwards to every listed address in one forward() action, then stops. If a staff member leaves the library, only the forward changes; the publisher never needs a new address.


// u + 4 hex digits, e.g. u1d7a@usr.example.com
String alias = String.format("u%04x", random.nextInt(0x10000)) + "@" + domain;

// One forward for every address, then stop. No forwards: stop() alone.
List<String> actions = new ArrayList<String>();
if (!forwards.isEmpty()) actions.add("forward(\"" + join(forwards, ", ") + "\")");
actions.add("stop()");

        What broke along the way (5)
        
    
          
  1. 
            
    HTTP 400 {"message":"invalid syntax (<unknown>, line 1)"}
    
            
    Mailgun reads a route's expression as code, and my first routes passed addresses bare, like match_recipient(u1d7a@…). Quoting the addresses inside match_recipient() and forward() fixed it.
    
            
          
    2. 
          
  2. 
            
    action=N/A
    
            
    Provided emails have nothing to forward to, and the screen shows that as "N/A". That placeholder was going out to Mailgun as a route action. Now an address with no forwards gets stop() alone, and since #6054, provided emails get no route at all.
    
            
          
    3. 
          
  3. 
            
    no active conversation
    
            
    Adding a customer-provided email failed with a Seam conversation error. An AJAX call was rebuilding the route expression on the entity while the form was still open. Building it once, on save, fixed it.
    
          
    4. 
          
  4. 
            
    Every "last updated" time came back as midnight.
    
            
    The column was a MySQL DATE, which keeps the day and drops the time. A DATETIME column, mapped as a timestamp, keeps both.
    
          
    5. 
          
  5. 
            
    The #6055 unit tests passed without testing anything.
    
            
    The test order items had no IDs, so every lookup came back empty and the checks never ran. Giving the fixtures IDs and emails made the tests real.

Tier info on Add Items
#6040 #6041

  
Publishers price institutions by tier, but order entry only showed WT Cox's internal "TIER 1" or "TIER 2", so the production team kept flipping to the publisher's page to work out the right one. Now each rate shows the publisher's own tier code with the details one tap away, and a vendor's own tiers win when it has them. This one was marked critical.

  

    

      Turn a fix off to see the old behavior
      
      
    

    
Order detail, Add Items tab. The Switch rate menu uses the same labels.

    

    

      How it's built
      
    
        
  • Vendor tiers live in a new table that mirrors the publisher's tier info, with a vendor where the publisher was.
    • 
        
  • Both kinds of tier row share one TierInfo interface, every field except the owner's ID, so the label, the details, and the Switch rate menu work with either.
    • 
        
  • A label reads like TIER 1 - Small: the internal tier, then every publisher code at that level.
    • 
        
  • In CoxNet2 the details sit in a tooltip on an info icon. Here they open in place, so they work on a phone too.
    • 
      


public interface TierInfo {
    Integer getLevel();
    String getTierCode();
    String getInstitutionType();
    String getDescription();
}

Cover Image Miner
Side tool, January 2025

  
CoxNet needed cover thumbnails for thousands of journals. I wrote a command-line tool that opens each title's page on the vendor's site, finds the cover, shrinks it to 200 by 267, and saves it under the title's ID, logging every miss with a link to check by hand. Over three days of runs it collected 3,772 of 4,070 ScienceDirect covers.

Tier lookup in SQL (#6040, #6041)

    
Reports needed the same tier labels and details as the screens, so the lookup also lives in MySQL functions. The label checks vendor tiers first, then the publisher's. The details come back as one string, joined for wherever it's going.


-- Vendor tier codes first...
SELECT GROUP_CONCAT(DISTINCT TRIM(vti.TIER_CODE) SEPARATOR ' / ') INTO result
  FROM VENDOR_TIER_INFO vti
 WHERE vti.VENDOR_ID = vendor_id AND vti.LEVEL = tier_level;

-- ...then the publisher's, if the vendor has none.
IF result IS NULL OR result = '' THEN
  SELECT GROUP_CONCAT(DISTINCT TRIM(pti.TIER_CODE) SEPARATOR ' / ') INTO result
    FROM PUBLISHER_TIER_INFO pti
   WHERE pti.PUBLISHER_ID = publisher_id AND pti.LEVEL = tier_level;
END IF;

-- The details function, last step: join the rows for their destination.
SET result = CASE p_format
  WHEN 'HTML'   THEN REPLACE(details, '|||', '<br />')  -- tooltips
  WHEN 'EXCEL'  THEN REPLACE(details, '|||', CHAR(10))  -- line breaks in a cell
  WHEN 'REPORT' THEN REPLACE(details, '|||', CHAR(13))
  WHEN 'PLAIN'  THEN REPLACE(details, '|||', '; ')
END;

  • 100 rows first. Data fixes ran on a small batch I could check by hand before they touched the rest.

Debug log: the platform

      
Errors that came from the stack itself, not the tickets.

      
    
        
  1. 
          
    java.io.IOException: invalid constant type: 18
    
          
    JBoss 4.2 couldn't deploy a class with a single lambda in it, because its bytecode reader predates Java 8. A plain Iterator loop fixed it, and Java 8 calls like Map.getOrDefault and java.util.Base64 got Java 7 rewrites.
    
        
    2. 
        
  2. 
          
    <a4j:ajax> Tag Library supports namespace: http://richfaces.org/a4j, but no tag was defined for name: ajax
    
          
    a4j:ajax is RichFaces 4. This app runs RichFaces 3, where the same job is a4j:support.
    
        
    3. 
        
  3. 
          
    HibernateException: Missing table: …
    
          
    Hibernate checks the schema when the app deploys, and the new join table wasn't on that database yet. Table changes go in the ticket's SQL script, run before the deploy.
    
        
    4. 
        
  4. 
          
    Error Code: 1005. Can't create table … (errno: 121)
    
          
    MySQL constraint names have to be unique across the whole database, and the quote item table reused a foreign key name from the order item table. Every constraint got its own name.
    
        
    5. 
        
  5. 
          
    Too many tables; MySQL can only use 61 tables in a join
    
          
    Eager loading on the new email links made Hibernate join every related table at once. Switching order items and quote items to lazy loading fixed it.
    
        
    6. 
        
  6. 
          
    Error Code: 1175. You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column
    
          
    Workbench's safe update mode stopped the default-email back-fill. I ran it on 100 rows first, checked them, then ran the rest.
    
        
    7.
